# 🔗 citation-verifier

Check every claim against the source it cites — and separate "the source
contradicts this" from "the source is simply silent about it", which is the
distinction that matters and the one everyone collapses.

```bash
uv run --with httpx python app.py
```

```
✅ c-01  verified      drift 0.09/3
     claim : The Series B round raised 48 million dollars.
❌ c-03  contradicted  drift 2.71/3
     claim : The Series B round raised 84 million dollars.
❔ c-04  unsupported   drift 1.40/3  🧑 review
     claim : Marchmont Ventures led the round and took a board seat.
🔀 c-09  wrong-source  drift 2.10/3  🧑 review
     claim : Nimbus Analytics uses a usage-based pricing model.
```

## The problem

RAG systems cite. That is the feature: every sentence carries a link back to the
document it came from, and the citation is what makes the answer auditable.

Except nobody audits it. The citation is generated by the same model that wrote
the sentence, from the same context, in the same pass — so a fabricated claim
comes with a confident, plausible, entirely real citation attached to a passage
that does not support it. Users trust the link precisely because it is there.
Spot-checking a sample by hand catches the crude failures and misses the
expensive one: a real source, about a real entity, that says something adjacent
to but not the same as the claim.

The failure that actually bites is not the invented citation. It is **c-04** —
the source says Marchmont led the round, the claim adds a board seat, and every
individual word of the claim is plausible.

## Why this needs Jev

Verification has to run on **every claim in every answer**, or it is theatre.
At $0.042 per million input tokens with free output, a claim-plus-source pair
put through five judgments costs a small fraction of a cent, so "check all of
them, on every response, in production" is affordable in a way a second frontier
call is not.

The structural property is the shape of the answer. Entailment is not one
number. `stated=0.1, contradicted=0.1` and `stated=0.1, contradicted=0.9` are
completely different situations that any single "faithfulness score" maps onto
the same low value. Jev returns **independent calibrated probabilities per
property**, so Python can tell them apart, and route only the genuinely
ambiguous ones to a human.

## How it works

Four Nouls and one Score per claim. `stated` and `contradicted` are deliberately
separate questions rather than two ends of one dial, because a source that says
nothing is neither:

```python
PROPERTIES = {
    "stated":        "Does the cited source state this claim, either in these words "
                     "or in plainly equivalent ones?",
    "contradicted":  "Does the cited source assert something incompatible with this claim?",
    "same_subject":  "Is the cited source about the same entity, product, period and event?",
    "needs_inference": "Does getting from the source to the claim require adding "
                       "something the source does not supply?",
}
```

`same_subject` is the guard for the citation that points at the wrong document
entirely — the Nimbus Analytics / Nimbus Logistics case, where the source is
real, well-written, and about a different company.

Ten claims × five judgments = 50 questions in **one request**. The verdict is a
pure function, and it reports its own uncertainty:

```python
def verdict(props, drift, *, support_p, contradict_p, subject_p):
    if props["contradicted"] >= contradict_p:
        return "contradicted", False
    if props["same_subject"] < subject_p:
        return "wrong-source", True
    if props["stated"] >= support_p:
        conflicted = props["contradicted"] >= contradict_p / 2 or props["needs_inference"] >= 0.7
        return "verified", conflicted
    return "unsupported", drift < 2.0
```

The review flag is the interesting half. A claim that is *unsupported but barely
drifts* is the one worth a human minute; a claim that is unsupported and wildly
off is obvious and needs no one's attention. That inversion is only expressible
because the drift Score and the support Noul are separate numbers.

## Run it

```bash
cp ../../../.env.example .env
uv run --with httpx python app.py
uv run --with httpx python app.py --support-p 0.8          # stricter: more unsupported
uv run --with httpx python app.py --json | jq '[.rows[] | select(.needs_review)]'
echo $?                                                     # 1 if anything is contradicted
```

## Design notes

- **Why the drift Score as well as the Nouls.** The Nouls say *whether* the
  source supports the claim. Drift says *how far* the claim travelled, which is
  what decides whether a human should look. Its levels are concrete situations
  so two reviewers agree on what a 2 means.
- **Why `needs_inference` does not on its own make a claim unsupported.** Most
  useful summarisation involves a small step. The app marks it and lets the
  threshold decide, rather than treating every inference as a failure.
- **Why `contradicted` is checked before `same_subject`.** A source about the
  wrong entity usually cannot contradict the claim at all, so a high
  contradiction signal on a wrong-subject pair means the model found a real
  conflict — worth surfacing as the stronger verdict.
- **Sources are supplied, not fetched.** The bundled sample pairs each claim with
  the passage it cites. Wiring this to your own store means replacing
  `sample_claims.json` with your retriever's output; nothing else changes.

## Limits

- **It verifies against the cited source, not against the world.** A claim can be
  perfectly supported by a source that is itself wrong. This catches
  fabrication, not falsehood.
- **Altered figures are caught as contradiction, not by arithmetic.** `jev-1.13`
  cannot count or do arithmetic. 48 vs 84 reads as an incompatible assertion,
  which works — but "the total is 12% higher than last year" against a source
  listing two figures is a computation, and this app will not do it. Compute it
  in Python and verify the computed statement instead.
- **No date reasoning.** "Superseded by a later document" is a date comparison
  and a documented failure mode. Sort by date in Python first.
- **One claim, one source.** A claim supported by the *combination* of two
  passages will read as unsupported against either alone. Pass the joined
  passage as the source if that is your retrieval shape.
- **Claim splitting is your job.** The sample arrives pre-split. A sentence
  carrying three separate assertions will get one blended verdict, so split in
  Python before you call this.
- **It reads literally.** Long, hedged, multi-clause claims are judged on exactly
  what they say — which is the behaviour you want from a verifier and
  occasionally surprising when the claim was sloppily written.
